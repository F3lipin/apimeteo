POR TRÁS DO PAINEL

Arquitetura e testes

Interface → API Gateway → microsserviços independentes. Esta versão utiliza um adaptador local de demonstração; não há backend meteorológico ativo.

01 · API Gateway

Ponto único de entrada. Encaminha solicitações, padroniza respostas e concentra tratamento de falhas.

02 · Geocoding

Busca localidades e retorna nome, estado, país e coordenadas. Resultados homônimos permanecem separados.

03 · Meteorologia

Recebe coordenadas e retorna condições atuais, código WMO e máximas e mínimas de cinco dias.

Contrato de integração

Configure uma URL HTTPS para o gateway no adaptador da aplicação. Rotas previstas: GET /geocoding/search?q=cidade → lista de localidades; GET /meteorologia/forecast?lat=…&lon=… → observação e days[5]. O gateway encaminha cada rota ao respectivo microsserviço. Os serviços não estão implantados nesta demonstração.

Roteiro de testes · 20 requisitos

Consulte Salvador; depois Rio de Janeiro, São Paulo e Recife; consulte Lisboa; verifique estado, país, coordenadas, horário, sensação, vento, UV, cinco dias, ícones WMO e gráfico. Teste entrada vazia, cidade inexistente e os dois resultados de “Salvador”. Compare cidades, atualize os dados e confira as últimas cinco consultas. Por fim, revise os contratos e a divisão gateway/geocoding/meteorologia acima. As consultas desta versão são simuladas: integração e testes de backend real dependem da implantação dos serviços.
